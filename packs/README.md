# Ziffr's starting Packs

Twelve Packs made by Ziffr (seven for kinds of business and for Ziffr itself, five for the functions of a business), under CC BY 4.0, so a new Workspace starts from a good setup instead of an empty page. Each is one file, and each comes with the app: install it on **Workspace → Packs** from **Ziffr's own Packs**, or from the file with **Choose a Pack file…** (an Owner, for the board meeting deck, since it holds a Theme). Installing adds Metric Catalog entries, templates, designs and Themes, and makes no Metric until you use them.

| File | What it holds |
| --- | --- |
| [`saas-metrics.pack.json`](saas-metrics.pack.json) | Version 2.0, the Pack that shows what a Pack can hold. MRR and its new, expansion and churned parts, ARR and revenue per account (Derived Metrics), customers, churn, net revenue retention, CAC and its payback, cash and runway, each with Tags; a monthly management report as a dashboard and as a deck; a quarterly board deck and the Workflow for the quarter's close with an Approval; the monthly close Workflow; a smoothed-growth Analysis Recipe and the View Design that draws it; a Theme that shows the Pack's logo. 13 Metrics. |
| [`online-shop.pack.json`](online-shop.pack.json) | Orders, online revenue (with a Breakdown by channel), average order value (a Derived Metric), conversion rate, return rate and sessions; a weekly dashboard; a Workflow Template that asks for the week's numbers on Monday. |
| [`agency.pack.json`](agency.pack.json) | Billable hours, utilisation, revenue, effective hourly rate, open invoices and pipeline; a monthly dashboard; a Workflow Template that asks for hours on Fridays. |
| [`sports-club.pack.json`](sports-club.pack.json) | Members, joiners and leavers, attendance per training, fees received and volunteer hours; a season dashboard; a Workflow Template that asks each coach for attendance after training. |
| [`board-meeting.pack.json`](board-meeting.pack.json) | A Deck Template for a quarterly board meeting of any kind of business (key figures, revenue against its target, cash and runway, headcount, highlights and risks), a Theme for it, the Metric Catalog entries it suggests, and a Workflow Template for the quarter's close. |
| [`workspace-usage.pack.json`](workspace-usage.pack.json) | Your own Workspace's usage as Metrics by day: views of dashboards, decks and Metrics, values by Source, and how many Metrics, dashboards and Submitters go unused; a "Workspace usage" dashboard. Counts only; held back in a Workspace of fewer than three people. Fed by the [Usage Feed](../docs/guides/usage.md) with `--workspace`; 18 Metrics, so mind the Workspace Limit. |
| [`ziffr-operations.pack.json`](ziffr-operations.pack.json) | One Metric by day for every figure of the [Usage Feed](../docs/guides/usage.md) (people, Workspaces, signups, trials, values by Source, calls, views), and a "Ziffr operations" dashboard. Set it up with the Feed as Submitter. |
| [`sales.pack.json`](sales.pack.json) | New and qualified leads, deals won and lost, closed-won value, pipeline, sales cycle, and win rate and average deal size worked out; a monthly dashboard; a Workflow that asks for the month's figures. Names the HubSpot and Google Sheets templates for the Metrics they fill. |
| [`finance.pack.json`](finance.pack.json) | Revenue, cost of goods sold, operating costs, cash and invoices, with gross margin and net result worked out; a monthly dashboard; a close Workflow that checks, asks one person to approve and locks the month. Names the Google Sheets and Excel templates. |
| [`people.pack.json`](people.pack.json) | Headcount, hires, leavers, open roles, time to hire, absence and engagement, with attrition worked out; a monthly dashboard; a Workflow that asks HR for the month's figures. Names the Excel and Google Sheets templates. |
| [`customer-support.pack.json`](customer-support.pack.json) | Tickets opened, closed and open, the old ones, first response and resolution times, satisfaction and reopens; a weekly dashboard; a Workflow that asks for last week's figures on Monday. Names the Google Sheets template. |
| [`fulfilment.pack.json`](fulfilment.pack.json) | Orders shipped, on-time delivery, backlog, stock, stock-outs, output, defects and downtime; a weekly dashboard; a Workflow that asks for last week's figures on Monday. Names the Google Sheets template. |

Each says whom it is for in an `audience` (see [Writing a Pack](../docs/guides/packs.md#whom-it-is-for)), so the Setup Guide can suggest the ones that fit a Workspace first. Nothing is ever hidden for it. SaaS metrics: software, B2B, management and finance. Online shop: e-commerce and retail, consumers. Agency or freelancer: agencies and professional services of one to fifty people. Sports club: non-profit. Board meeting: management and finance. Each function Pack (sales, finance, people, customer support, operations and fulfilment) names its function; fulfilment also names the industries that ship goods. Workspace usage and Ziffr operations have none: they are for whoever runs the Workspace or the Installation, and their summaries say so. Their `ziffr` minimum stays at 0.11 so the files install on every Ziffr that ships them; an older Ziffr than 0.16 refuses the `audience` field, as the check says.

Where a Metric of the Metric Catalog fits, an entry uses its name and description, so the catalog and the Packs say the same thing. Tests check every file with the checks Ziffr runs on any Pack (`starting-packs.test.ts`) and install all twelve into one Workspace, and set each business-function Pack up whole (`starting-packs.db.test.ts`). Check a changed file yourself with `npx @ziffr/pack check packs/<file>`, and raise its version.
